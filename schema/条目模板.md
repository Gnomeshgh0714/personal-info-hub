# 条目模板（人读四段式 · 与 personal_info.jsonl 字段对齐）

> 蓝本：四段式经历条目（通用版表述 / 场景版表述 / 证据映射表 / 待确认清单）。
> 本模板把这套文体对齐到机读字段：人写条目照这四段填，机读条目照下面的 JSON 填，两边字段一一对应。
> 采集器自动产出的条目只填「事实 + 证据映射」两段；「简历表述」两段留给人写，采集器不生成话术。

---

## 一、事实（采集器产出，机读字段的来源）

**{名称}**

- **分类**：实习经历 / 项目经历 / 获奖荣誉 / 技能资产 / 论文作品 / 教育背景（六选一）
- **时间**：{起止时间，照源文件原样抄，不做推算}
- **角色**：{岗位 / 身份 / 职责定位}
- **成果**：{做了什么、产出什么，一到三句陈述}
- **量化值**：{成果里出现的数字，逐个列出，每个都要能回到源文本定位}

## 二、简历表述（人写，采集器不生成）

### 通用版（技术栈已压缩）

- {表述}

### AI 岗版（保留技术栈）

- {表述}

> 排名、GPA、教育背景一类事实只登记在第一段，不自动改写成这里的表述。
> 写表述时遵守简历项目既有纪律：严禁虚假量化，源材料写「目标」就保留「目标」字样。

## 三、证据映射（表述 / 事实 → 来源路径）

|---|---|---|
| {一句话事实} | `{源文件绝对路径}` | {行号 L12-L18 或节名「实习经历」} |
| {无直接文件证据的项} | 用户 {日期} 口述定稿 | 诚实标注，不留空 |

## 四、待确认清单

1. {需要人工核验或裁决的点}
2. {主源冲突时列出各源差异，不自动选边}

## 机读字段对照（personal_info.jsonl 一行一条）

```json
{
  "id": "PI-1001",
  "版本": 1,
  "分类": "实习经历",
  "名称": "示例咨询公司 · 咨询实习生（数字化转型方向）",
  "时间": "2026 年 6 月 -- 至今",
  "角色": "咨询实习生",
  "成果": "参与行业数字化转型专题研究，独立完成行业标杆研究报告",
  "量化值": [{"值": "3 份行业标杆研究报告", "定位": "L109", "已溯源": true}],
  "无源量化值": [],
  "来源盘": "demo",
  "来源工作区": "示例工作区",
  "源清单": "demo-简历",
  "证据路径": ["/path/to/简历.tex"],
  "证据定位": "节「实习经历」L108-L118",
  "采集时间": "2026-11-11T00:00:00+08:00",
  "采集方式": "全量扫描",
  "扫描模式": "full",
  "状态": "待核验",
  "主源冲突组": "简历多源",
  "简历场景": "求职-润色版（最新求职版）",
  "主源裁决": "人工裁决：多源并存、按场景归类、不选唯一权威源；只定主源归属场景，不裁决内容真伪，状态仍为待核验",
  "记录哈希": "a1b2c3d4e5f60718"

```

### 字段口径

| 字段 | 口径 |
|---|---|
| `id` | `PI-` + 四位序号，首次入库时分配，此后同一条事实永远沿用，不因重扫而变 |
| `版本` | 同一 `id` 第几次落盘。下游视图按「同 id 取最后一行」聚合，旧行不删不改 |
| `分类` | 六选一：实习经历 / 项目经历 / 获奖荣誉 / 技能资产 / 论文作品 / 教育背景 |
| `名称` | 条目标题，照源文件原样，不做美化 |
| `时间` | 源文件里的原始时间表述；源里没有时间就留空字符串，不推算。从文件名抽日期时过三重校验（前后不紧邻数字、月 1–12、日不超该月真实天数），校验不过就留空，绝不硬塞一个不可能的日期 |
| `角色` | 岗位、身份或职责定位；无则留空 |
| `成果` | 事实陈述，一到三句；不写形容词、不写推测 |
| `量化值` | 数组，每项 `{值, 定位, 已溯源, 上下文}`。`定位` 是**数字级**行号（该数字在源文件哪一行），`已溯源=false` 表示数字在源文本定位不到 |
| `无源量化值` | 数组，把本条里 `已溯源=false` 的值原样列出。这个字段**不看状态**：即使 `状态` 已被「主源冲突」或「需OCR人工录入」占用，定位不到的数字仍会记在这里，无源信息不会丢 |
| `来源盘` | 源根所在盘/主机的标签，来自源配置 `盘` 字段 |
| `来源工作区` | 源根所属工作区名，来自源配置 `工作区` 字段 |
| `源清单` | 命中 `collector/sources.json` 里哪一条源，便于回溯采集范围 |
| `证据路径` | 数组，源文件绝对路径；一条事实跨多文件时全列 |
| `证据定位` | **条目级**定位：整条事实在源文件里的行区间（`节「实习经历」L103-L109`）。与 `量化值[].定位` 的数字级行号是两回事，不可互相覆盖 |
| `采集时间` | ISO 8601 带时区 |
| `采集方式` | `全量扫描` / `会话提取` / `人工` |
| `扫描模式` | `full` 或 `incremental`，记录该行是哪一轮扫出来的 |
| `状态` | `待核验` / `已核验` / `主源冲突` / `无源待确认` / `需OCR人工录入` |
| `主源冲突组` | 同一事实互为备选的多个主源的分组名（如 `简历多源`）。按场景归类后不再以状态为条件：多源按场景并存、状态回到待核验，组名仍留着当场景分组身份；采集器只标组不选边 |
| `简历场景` | **仅参与场景归类的条目有，空则不写这个字段**。场景标签由 `collector/sources.json` 的 `简历场景映射` 人工配置（如 `求职-原始版` / `求职-润色版` / `保研版`），采集器只读取、不推断 |
| `场景警示` | **仅命中警示规则的条目有，空则不写**。规则存于源配置 `场景警示规则`：`场景含` 匹配场景标签、`文本匹配` 正则命中名称/成果时写入 `警示` 文案。示例：保研场景的排名/成绩类条目禁止流入求职简历表述；语言考试成绩不配进规则，因为两个场景都写 |
| `主源裁决` | 有 `简历场景` 时写入的裁决依据原文（来自源配置 `主源裁决`），**空则不写**。让人工核验时不必回翻配置就知道这条为何不再标冲突 |
| `记录哈希` | 内容指纹（排除 id/版本/采集时间/扫描模式/记录哈希）。哈希不变则重跑不追加新行，这是幂等的依据 |

### 状态取值与流转

| 状态 | 含义 | 谁能改 |
|---|---|---|
| `待核验` | 文本类源正常解析出条目，事实与证据齐备，等人过目 | 人工核验后置 `已核验` |
| `已核验` | 人工确认事实与数字无误 | 只能由人置，采集器永不自动置 |
| `主源冲突` | 同一事实在多个主源（如三份简历 tex）里表述不一致，且尚未裁决 | 人工裁决后按场景归类改 `待核验`，或择一源改 `已核验` |
| `无源待确认` | `无源量化值` 非空（有数字在源文本定位不到），或整条无文件证据 | 人工补证后改 `待核验`；补不到就删条目 |
| `需OCR人工录入` | PDF / 扫描件 / 图片只登记了路径与元信息，内容未解析 | 人工录入后改 `待核验` |

> `需OCR人工录入` 是四个基础状态之外为二进制登记项增开的第五个取值，只用于 v1 不解析内容的文件类型。

> 状态只能取一个值，但无源事实可能发生在任何状态的条目上（一条显式标了「主源冲突」的条目也可能同时含无源数字）。
> 所以无源判定不依赖状态：`无源量化值` 字段一律写全，`待核验队列.md` 的「无源待确认」区也按该字段取数，
> 因此同一条目可能同时出现在冲突区与无源区（队列头部总数按 id 去重）。

> **场景归类对状态流转的影响**：参与场景归类的多源条目不再一律标「主源冲突」，而是按场景并存后回到「待核验」。
> 裁决只定「主源归属哪个场景」，**不裁决内容真伪**，所以这些条目既不会置「已核验」，也不会从队列消失（仍在第四节等人过目）。
> 安全阀：若 `sources.json` 的 `简历场景映射` 漏配了某个 `主源冲突文件`，该文件的条目仍标「主源冲突」（未裁决），避免映射漏配导致冲突标记被静默丢掉。
